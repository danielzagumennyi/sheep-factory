# Овечья фабрика — техническое ТЗ

Устроено так же, как Cubocalypse («3d survival»): pnpm-воркспейс, React Three Fiber, koota, zustand, Vite, TypeScript strict, Vitest.

## 1. Стек

| Что | Чем |
|---|---|
| Сборка | Vite 8, `base: './'` в сборке, поэтому папку `dist` можно выложить куда угодно |
| 3D | three 0.185, @react-three/fiber 9, @react-three/drei 10 (`Html` для подписей на поле) |
| Состояние мира | koota 0.6: ресурсы мира (`res(world, X)`) |
| Состояние интерфейса | zustand 5 (`app/store.ts`, `ui/hudStore.ts`, язык) |
| Тесты | Vitest 5 в Node, без отрисовки |
| Стиль | ESLint 9 + typescript-eslint, Prettier: `semi: false`, `singleQuote`, `printWidth: 200` |

Физики нет: игра на сетке, Rapier не нужен.

## 2. Пакеты

| Пакет | Что это |
|---|---|
| `packages/game` (`@ws/game`) | Игра. `pnpm dev` |
| `packages/input` (`@kit/input`) | Действия клавиатуры по `KeyboardEvent.code`: `held()` и `on()` |

Правило как в Cubocalypse: `@kit/*` — переиспользуемые библиотеки. Они не импортируют `@/`, у каждой один вход `src/index.ts`.

## 3. Симуляция (`packages/game/src/game`)

Это чистый TypeScript без React и three. Его гоняют тесты и бот в Node.

| Файл | Что в нём |
|---|---|
| `balance.ts` | все числа, таблица уровней деревни (`LEVELS`) и карта (`START`, `MAP_TERRAIN`) |
| `land.ts` | клетки прямоугольников и пятен для карты (`RECT`, `BLOB`) |
| `world.ts` | типы данных, ресурсы koota, `createGameWorld` |
| `start.ts` | `startWorld` = мир, первый уровень деревни и стартовые карточки |
| `grid.ts` | чистые вопросы о сетке: что стоит, чья клетка, радиус добычи, `whyNot` (с Баней у воды: `waterNear`), цены |
| `systems/` | системы шага: `belts`, `machines` (с посевом), `sheep`, `village` (рынок, клиенты, уровни, торговля, рост острова), `unlocks`, а в `index.ts` порядок шага |
| `actions/` | команды игрока: `build` (стройка, снос, покупки), `path` (ленты по двум кликам), `hand` (клики рукой) |
| `plan.ts` | готовая схема фермы главы 1 по клеткам: что строит бот и что стоит за главным меню |
| `bot.ts` | бот баланса |
| `showcase.ts`, `stress.ts` | ферма за меню и огромная фабрика для замеров |

### 3.1 Ресурсы мира
`Time`, `GameState` (часы, монеты, уровень деревни), `Field` (рельеф, запасы клеток, всходы, участки, холмы `hills`, кучки на земле `piles`, края острова `left`, `top`, `right`, `bottom`), `Plant` (постройки по клеткам), `Flock` (овцы, загоны), `Market` (клиенты рынка: товар, спрос в минуту, довольство), `Stock` (склад рынка: счётчик товаров без предела), `Unlocks` (открытое, карточки, события), `Ui` (инструмент, поворот, выбор, наведение, вещи в руке `carry`), `Fx` (очередь эффектов), `Stats`, `Rng` (детерминированный, `rng.ts`), `Systems` (какие системы включены, 3.4).

Постройки, вещи и овцы — это обычные объекты внутри ресурсов. Постройка лежит в `Plant.b` под своей верхней левой клеткой, остальные клетки станции 2×2 ведут к ней через `Plant.occ`; `get(x, y)` находит постройку по любой её клетке, `outCells(b)` даёт клетки её выходов, `inCell(b)` — её единственный вход (задняя клетка на линии выхода), `machineIns` и `inCells` — все входы с тем, что каждый берёт (у станции овца сзади, у Кормушки и Покраски ещё товар справа, у сеялки семя), `entersAt` решает, примет ли постройка товар, пришедший в эту клетку с этой стороны. Станция хранит на входе до `BELT.bufMax` своего товара (`BUILDINGS[t].uses`). Что даёт Стрижка, решает `shearYield` (`systems/machines.ts`) по меткам овцы `SheepT.marks`: сколько из `STEPS` она прошла (`SHEAR_YIELD`), была ли в Бане (`BATH_YIELD`), в Покраске (`COLORED`). Ключ — клетка `"x,y"`: правила всё время спрашивают о сетке («что на этой клетке», «кто кормит эту ленту»). Так же сделаны пулы в Cubocalypse: koota держит только ресурсы мира.

Овца, въехавшая в чужой загон, переходит в состояние `transit` (`crossPen` в `systems/sheep.ts`): идёт к выходу загона и уезжает дальше, `via` — какой загон она пересекает. Чужой загон её пускает, только если на его выходе есть лента или станция и пересекают его не больше двух овец. `loopHasFeeder` ищет кормушку по петле сквозь чужие загоны.

`beltAutoDir(w, x, y, rot)` — направление одной ленты среди соседей: баллы за то, кто примет груз (`handOnScore`), прямое продолжение от кормящего, штраф за разворот в кормящего; `rot` (R) разрешает ничьи. `pathDirs` зовёт его для линии из одной клетки. `GameState.plantVersion` растёт при каждой постановке, снятии и повороте — по нему сбрасывается кэш маршрутов `routeCells`.

### 3.2 Шаг
`stepSimulation(world, FIXED_DT)`, шаг 1/60 с, идёт по таблице `STEPS` (`systems/index.ts`): каждый шаг под именем своей системы и делается, только если она включена. Порядок такой:
1. клиенты рынка;
2. овцы;
3. всходы;
4. подсказка про участки;
5. вещи на лентах;
6. машины (станции, добытчики, сеялки, цеха).

Пока поднята карточка «Новое», стоит пауза или открыто меню, мир не идёт (`isFrozen`).

### 3.3 Эффекты
Симуляция ничего не рисует и не играет. Она кладёт в `Fx` события «число всплыло», «облачко» и «звук». Вид разбирает очередь каждый кадр. Без отрисовки очередь ограничена 400 событиями.

**Падение в кучку** (`fall`). `putPile` с `from` (точка и высота, откуда вещь взялась) кладёт событие на каждую вещь: клетка, место в кучке, товар, откуда, номер в падении. Его разбирает не `FxView`, а `collectFrame` (`render/frame.ts`) — до того, как рисует кучки, иначе вещь на кадр показалась бы на месте до полёта. `render/falls.ts`: `startFall`, `stepFalls` — дуга (`FALL.base` + `FALL.perCell` на клетку, высота `FALL.arc`), вещи одного падения по очереди через `FALL.stagger`, на месте прыжок `FALL.hop` за `FALL.bounce` и облачко пыли (`puffAt` из `FxView`). Пока вещь в воздухе, её место в кучке пусто. Взяли кучку раньше — падение пропадает. Отпущенное из руки (`FallFrom.hand`, событие `hand`) `collectFrame` пускает с того места, где эта вещь была нарисована в стопке прошлым кадром (`frame.carry[n]`): все разом, прямо вниз с ускорением `FALL.gravity`, без дуги; по дороге вещь из «как в руке» (размер, высота, поворот — `GoodSpot.held`) становится «как в кучке». Откуда падают остальные: стрижка рукой — со спины овцы (`HAND.fallFrom`), рука без стопки на экране — с высоты `HAND.carryAt`, машина — со своей клетки у выхода, лента — со своей клетки, снесённая постройка — с её середины, сдвинутая кучка — с её клетки.

**Звуки** (`src/audio/index.ts`) — пока только записи автора из `public/sfx`: `place` (постройка поставлена), `remove` (снесена) — события симуляции; `click` — любая кнопка интерфейса (слушатель на странице). Файл грузится и декодируется Web Audio при первом звуке; тот же звук не чаще раза в 70 мс.

### 3.4 Системы и выключатели
Игра разбита на системы с именами (автор, 17.10.2026: «игра должна быть разбита на системы и их легко должно быть отключать»). Список — `SYSTEMS` в `world.ts`, мир держит включённые в `Systems.on`, проверка — `isOn(world, id)`. Набор задаётся при создании мира: `startWorld({ systems })`.

| Система | Что делает | Где проверяется |
|---|---|---|
| `clients`, `sheep`, `sprouts`, `hints`, `belts`, `machines` | шаги симуляции | `stepSimulation` |
| `village` | товар, привезённый на рынок, идёт на склад; уровни открываются с карточками, остров растёт | `dockAccept`, `clientSystem` |
| `floats`, `sound` | всплывающие числа и звуки | `emit` |
| `keys` | клавиши на поле: инструменты, поворот, снос, пауза, камера (Esc и Enter для карточки, справочника и меню работают всегда) | `GameLoop` |
| `pointer` | мышь и тачпад на поле: рука, стройка, камера | `Scene` |
| `ghost` | что в руке: предпросмотр, сетка клеток, зона сбора | `Scene`, `Ground` |
| `hover` | обводка и подпись под курсором | `Scene` |
| `tags` | подписи на поле: цены участков, счёт у загонов, значки над машинами и овцами | `Scene`, `Pastures`, `Machines`, `SheepView` |
| `hud` | панели экрана | `GameLoop` |
| `portIcons` | значок у каждой стрелки входа и выхода (`inGood`, `outGood` в `grid.ts`, `badgeMaterial` в `render/iconSprite.ts`) | `Ghost` |
| `fps` | счётчик кадров | `Scene` |
| `orbit` | камера сама медленно облетает ферму | `Scene` |

`PLAY` — игра: всё, кроме `orbit`. `DEMO` — ферма за главным меню, только посмотреть (автор: «в демо на главном меню должно быть только визуально»): работают овцы, ленты, машины и всходы, камера облетает ферму; клиенты рынка ничего не берут. Ни клавиш, ни мыши на поле, ни сетки, ни чисел, ни подписей, ни звука, ни уровней. Новая система — новое имя в `SYSTEMS` и одна проверка там, где она работает.

### 3.4.1 Рынок и клиенты
Рынок — одна постройка `dock` 8×8 в `MARKET.x`, `MARKET.y` (`addMarket` в `world.ts`). Её нельзя снести и поднять.

У рынка восемь входов (`MARKET.ports`: на каждой стороне две клетки от угла; `dockIns` в `grid.ts`, они же `inCells` рынка — розовые стрелки). Лента или выход машины, который смотрит во вход, сдаёт товар через `dockAccept(w, d, it, x, y, dir)`; рядом со входом рынок не берёт (`entersAt`), лента там стоит:
- Овцу рынок не берёт: она ждёт на ленте.
- Товар идёт на склад, пока там меньше `MARKET.keep` этого товара. Сверх этого рынок сразу продаёт его за ¼, поэтому линия не встаёт.
- В любом случае приходит событие `deliver` с клеткой рынка и клеткой, откуда товар пришёл (`fx`, `fy`).

Клиенты — `Market.needs` (`NeedT`): клиент, товар, `rate` в минуту, `due` (сколько штук пора взять) и `fill` (довольство, 0…1). `clientSystem` каждый шаг копит `due`. На каждую штуку он берёт товар со склада: взял — платит полную цену и даёт событие `take`. Довольство — скользящее среднее: `fill += (взял − fill) · fillStep`, где `fillStep = min(1, 60 / (rate · CLIENT.fillSec))`. Так полоска показывает долю штук за последние `CLIENT.fillSec` секунд и у каждого клиента тянется одинаково быстро. Полная полоска — от `CLIENT.content` (95%). Кормить наполовину — полоска стоит около половины.

Все полные (`allContent`) — `openLevel` следующего уровня. Он открывает новое, ставит каждому клиенту спрос уровня (`LEVELS[i].needs`), добавляет нового клиента и сбрасывает все полоски в ноль. Клиент не уходит никогда. После таблицы спрос растёт в `AFTER.grow` раз за уровень (`levelDef`).

Торговля (`sell`, `buy`) — только с `GameState.trade`, его включает уровень торговли; в окне рынка, под его клиентами.

### 3.5 Сохранение
`game/save.ts` — чистый: `saveGame(world)` отдаёт всю игру как JSON, `loadGame(data, opts)` строит из неё мир, который идёт дальше точно так же, как шёл бы сохранённый (в сохранении и состояние генератора `Rng.next.state`). Ресурсы мира — массивы вместо `Map` и `Set`; вещь с овцой и овца в машине хранят номер овцы; `Plant.occ` строится заново. Не сохраняются очередь эффектов, включённые системы и разовые карточки (их хранит приложение). Постройка в руке при переносе сохраняется на старом месте; овца в руке опускается там, где была, и бродит; вещи в руке остаются в руке (`ui.carry`); кучки на земле — в `field.piles`. Игра на паузе загружается идущей.

У сохранения номер формата `SAVE_VERSION` (сейчас 7). Когда формат меняется, номер растёт на один, а в `MIGRATE` встаёт шаг от прежнего. Сохранения до 7-го сделаны на карте до квадратной (21.10.2026): их клетки — не клетки этой карты, поэтому шагов от них нет и они не загружаются. Холмы не сохраняются: они берутся с карты. Сломанное сохранение, чужое или от более новой сборки не загружается (`null`). Приложение тогда его стирает.

Где оно лежит — `app/saves.ts`: по сохранению на режим в `localStorage`, всё в try/catch (в приватном окне игра просто не хранится). Длинная игра лежит под `ovf.game`, бесконечный режим — под `ovf.endless`. Режим мира — `GameState.endless`, по нему `writeSave` выбирает место. `RunScreen` пишет его сразу (новая игра занимает место старой), каждые `SAVE.everySec` секунд, когда страница прячется (`visibilitychange`, `pagehide`) и при уходе с экрана. Главное меню читает `savedInfo(mode)` — уровень и время — и показывает «Продолжить»; `useAppStore.cont(mode)` запускает экран игры с `from: 'save'`, `start(mode)` — новую (без режима — тот, что был последним). Тесты — `save.test.ts`: бот играет 20 минут, мир сохраняется через JSON и загружается, оба идут ещё 5 минут шаг в шаг и совпадают; рука и перенос; сломанные сохранения.

## 4. Отрисовка (`packages/game/src/render`)

### 4.1 Цикл кадра
`GameLoop` — единственный `useFrame(..., -100)`. Он делает пять вещей:
- накапливает время × скорость и делает фиксированные шаги (до 8 за кадр);
- собирает `frame` — где сейчас каждый товар и каждая овца (`frame.ts`);
- раз в 6 кадров обновляет HUD;
- обрабатывает клавиатуру;
- держит консоль `__game`.

### 4.2 Виды
- **Земля.** `Ground` — остров-диорама: травяной верх с бортиком над земляными боками, висит на голубом фоне. Верх — сетка вершин с нарисованной текстурой (участки, поля под покосом). Высота следует за прудами: каждая клетка воды — ямка с зелёным бортиком и земляными стенками, глубина по запасу воды, сверху одна общая гладь. Перерисовывается только по `fieldVersion`.
- **Мелкие объекты.** Всё, чего много, рисуют instanced-сетки (`instancing.ts`, `Batch`): `Terrain` (снопы на пашне ниже по мере покоса, пруд мелеет, ягоды пропадают), `Belts`, `Items`, облачка.
- **Ленты.** Деревянные, как в Tower Factory: тёмное ложе, светлые поперечные планки бегут вместе с товаром, бортик на каждой стороне, через которую лента не проходит. Клетка — два полуотрезка (поворот читается буквой Г), на повороте круглая площадка вместо пересекающихся планок.
- **Объекты по одному.** У машин, овец и рынка по своему компоненту.
- **Подписи на поле.** drei `Html`, `pointer-events: none`.
- **Предпросмотр** (`Ghost.tsx`, по второму снимку Tower Factory от автора). Здание и лента в руке выглядят одинаково.
  - Модель в своих цветах, поднята на 0,24 клетки. Под ней — полупрозрачный голубой блок до земли размером с основание (`blockOf`: дно на каждой клетке, стенки только по краю, так что под линией ленты один блок). Стенка, смотрящая на экране влево, светлее, вправо — глубже; внизу плотнее, вверху прозрачнее.
  - Кремовая обводка `@kit/outline` (оттенок `place`) только вокруг модели.
  - Вход — розовая толстая плоская стрелка у входной стороны, выход — голубая у выходной, на высоте основания, в 0,3 клетки от края. У наведённой машины те же стрелки висят над лентами.
  - Если поставить нельзя: красный блок, красная обводка (`blocked`), модель чуть краснее, причина над ней.
  - У добытчика всё внутри круга сбора окрашено холодным голубым (`reach.ts`), по краю лимонное кольцо, от каждого ресурса, который он возьмёт, — лимонный пунктир до его основания.
  - Лента в руке: настоящие куски (`drawBelt`) на одном блоке, розовая стрелка в начале линии, голубая в конце, цена у курсора.
  - Сетка — тонкие тёмные линии. Пузыри на время стройки скрыты, ценники участков приглушены (класс `is-building`).
  - Участок на продажу под рукой подсвечивается целиком тем же блоком, что место под здание (`showBlock` в `Ghost.tsx`), красным — пока его не купить; подписи покоса и кустов на нём нет. Ценник (`PlotTags.tsx`) и окно участка — в его середине.
  - Поставленная машина опускается с высоты 0,24 и приседает (`DROP` в `Machines.tsx`), `place()` выпускает облачко пыли.
- **Сетка клеток.** Отдельный прозрачный слой над землёй, виден только при выбранном инструменте стройки.
- **Мышь.** `Pointer` — луч на плоскость земли, затем те же правила, что в прототипе.
- **Что под курсором** (`pickAt` в `pick.ts`). Берётся ближайшая модель, в которую упирается луч: овца (по своей модели в позе), машина (по всей модели, сначала коробка вокруг), причал. Дальше земли луч не идёт. Если не попал ни во что — овца у точки на высоте спин, потом постройка на клетке под курсором. `Hover` ищет это каждый кадр, клик рукой по модели машины идёт этой машине (`clickBuilding`).
- **Экраны** (`app/App.tsx`). `title` — главное меню (`TitleScreen`: мир с системами `DEMO` и готовой фермой главы `buildShowcase`, залежи полны; `ui/Title.tsx`), `run` — игра: длинная или бесконечный режим (`useAppStore.mode`). Бесконечный режим — `startWorld({ endless: true })`: `openEverything` в `systems/village.ts` до первого уровня открывает всё, что открывают уровни, поднимает остров целиком и помечает все карточки показанными. `?play` в дев-сборке сразу запускает игру, `?play&endless` — бесконечный режим.
- **Пауза.** Одна — `GameState.speed` = 0. На паузе `handClick` только открывает окна (`handStill`), Pointer не берёт овцу; попытка тронуть поле увеличивает `pauseNudge`, и строка паузы вздрагивает. Пока камера крутится правой кнопкой, Pointer обновляет место курсора, поэтому наведение идёт за курсором.
- **Окно здания.** `MachineLoad` в `Hud.tsx`: `jobProgress`, `cycleTime` (`systems/machines.ts`), места каждого товара `inv` из `BELT.bufMax`. Загрузки со склада нет: товар в машину приходит лентой или в руке (`dropCarry`). У Стрижки — её строки (`shearLines` в `Hud.tsx`): что даёт овца после скольких станций. Здесь же семя сеялки (`setSeed`) и правила делителя (`cycleRule` по товарам, что уже встречались).
- **Подсветка** (`@kit/outline`): отмеченный объект не рисуется в проходе, а пиксели рядом с ним (8 направлений на полную и половину толщины) берут его цвет — линия снаружи. Стрелки входов и выходов (`Ghost.tsx`) без проверки глубины, поверх всего. Меню и справочник ставят её сами и возвращают прежнюю скорость (`uiPause` в `GameLoop`), поэтому ❚❚ всегда показывает, что игра стоит. `isFrozen` — только пауза и карточка «Новое».
- **Панель и справочник.** Ячейки панели — `bar` в `app/store.ts` (`ovf.bar`), показ — `barOf`: своё место у постройки, ещё не открытая оставляет ячейку пустой, открытая без места занимает первую пустую. Клавиши 1–0 (`tool1…tool10`), B — справочник (`ui/Book.tsx`): клик строит, клавиша над плиткой — `assignSlot`. Пока справочник открыт, мир стоит (как под меню).
- **Один принцип для всех построек** (автор). Входы — `inCells`, выходы — `outCells` (`grid.ts`), из них же строятся розовые и голубые стрелки и при постановке, и при наведении (`showFlow` в `Ghost.tsx`): у машины вход сзади (у Кормушки и Покраски ещё справа: `machineIns`), у делителя вход сзади и три выхода, у объединителя три входа и выход, у ленты вход и выход, у причала входы со всех сторон, куда дотянется лента. Наведение обводит любую постройку и загон (`Hover.tsx`), правая кнопка поднимает любую, кроме причалов. У делителя и объединителя своя модель на куске ленты (`machineModel`), та же в руке, на поле и на значке.
- **Перенос** (`liftUp` / `putDown` / `putBack` в `build.ts`). Правая кнопка по машине или кнопка в её меню поднимает машину со всем, что в ней лежит; она держится, как новая постройка, и встаёт по клику бесплатно. Esc, правая кнопка или другой инструмент возвращают её на место. Так же переносятся ленты, делители и объединители; не переносятся только причалы. Зона сбора — круг радиусом `REACH` от середины машины (`reachCells`), тот же круг в шейдере `reach.ts`. Луч берёт ленту по плите высотой с её бортик (`pickAt`), а подсветка рисует наведённую клетку ленты ещё раз в буфер обводки (`Hover.tsx`).
- **Рука и кучки** (GDD 3; `PILE`). Ничего не засчитывается и не прыгает само. Кучки — `Field.piles` (по клетке, до `PILE.max`); `systems/ground.ts`: `dropNear` кладёт вещи на клетку или ближнюю с местом (`pileOk` в `grid.ts`: остров, не холм, не вода, камень, дерево, загон или постройка), `putPile`, `takePile`, `shiftPile` (постройка, поставленная на кучку, сдвигает её). В кучку падает: настриженное рукой (`shearClick`; на соседнюю клетку, к которой овца ближе, — `besideOf`, а не под овцу), выданное машиной без ленты (`pushOut`; машина ждёт, если кучка полна), всё из снесённой постройки (`remove`), товар, застрявший перед путём овец (`beltSystem`), семена сеялки при смене (`setSeed`), купленное в окне рынка (`buy`, у входа рынка). Рука — `Ui.carry` (до `PILE.max`) и `carryFrom`, сохраняются в сохранении; сбор (`gather`) кладёт прямо в руку, с полной рукой — рядом; `actions/hand.ts`: `pickUp`, `pickFromBelt`, `dropCarry` (рынок — `marketTake` всё; голодная овца — `feedSheep` одно сено; пустая лента — одна вещь; машина — её входы, `machineAccept`; земля — кучка; остаток в руке), `putDownCarry` (правый клик, Esc). Клик и перетаскивание — `Pointer.tsx` (отпущенное над моделью идёт в эту постройку); стопку в руке рисует `Items.tsx` поверх всего, с тенью, на высоте `CARRY_Y` над точкой поля под курсором (`groundHit` в `pick.ts`: верх холма или земля — та же точка, куда пойдёт клик); что в руке, видно и в HUD (`HandPanel`). Кучки лежат только на своей земле. Склад (`Stock`, `stockAdd`, `stockTake`) — только склад рынка: в него кладёт `marketTake`, берут клиенты и `sell`. Овцы не прыгают: со снесённой постройки, из рук и мимо полного загона они бродят там, где оказались (`toRoam`). Купленная овца появляется там, где кликнули (`buySheepAt` в `actions/build.ts`): в загоне со свободным местом или на своей траве, бродячей. Сначала она спускается на парашюте: `SheepT.drop` — сколько секунд ей осталось (`DROP.fall` в воздухе и `DROP.land` на траве). Пока он есть, система овец её не трогает, а `sheepAt` её не находит; на касании `land` пускает облачко, звук и сердечко. Рисует полёт `dropPose` в `render/sheepLook.ts`: овца качается маятником под куполом, у земли сплющивается и пружинит, купол заваливается. В сохранении поле необязательное, старым сохранениям шаг формата не нужен. Остриженная овца голодна (`fed` = false, `hungry` в `systems/sheep.ts`); шерсть растёт `SHEEP.grow` секунд только у сытой — поевшей в кормушке (`stationTake`) или покормленной рукой (`feedSheep`). Голодная выходит на петлю, только если на петле её загона стоит кормушка с сеном (`loopHasFeeder` проходит петлю раз в секунду); иначе над загоном пузырь сена. Клиенты рынка берут свой товар со склада (`clientSystem`, 3.4.1); торговля — `sell` и `buy` в окне рынка по `sellPrice` (¼ цены) и `buyPrice` (`BUY_SHARE` = 2 цены). Слева внизу, над счётчиком кадров, — `StockPanel` в `Hud.tsx`.
- **Бродячие овцы** (`roam` в `systems/sheep.ts`, числа — `ROAM` в `balance.ts`). Состояние `roam`, `home` = 0.
  - Цель — точка в пределах `reach` клеток, до которой видна прямая дорога (`clearWay`) и вокруг которой есть место (`roomy`).
  - Ходить можно по своей земле без построек, загонов и `ROAM.blocking` (`walkable`); лента проходима, но цели на ней не бывает (`grazeable`).
  - Если под овцой выросла постройка или загон, она переносится на ближайшую свободную клетку (`nearestGround`).
  - `toRoam` — общий вход: старт игры, рука (`dropSheep`, и мимо полного загона), станция без ленты на выходе (`pushOut`), снесённая постройка или лента с овцой, пропавший загон.
  - Над лентой овцу поднимает `frame.ts` (`lift`).
- **Загон** — постройка 3×3 в `Flock.pastures` (`makePen`), не в `Plant`; ставится `place(w, 'pen', …)`, сносится только пустым. **Вход и выход загона** (`exitOf`, `entryOf`). Выход — середина стороны `dir`, вход — середина стороны на четверть оборота левее, со своим направлением. Лента отдаёт в загон только овцу и только с клетки входа в его сторону (`entersPasture`). Путь ленты к загону сам идёт к входу (`routeCells`).
- **Часы анимаций** (`frame.t` в `frame.ts`). Всё, что движется на поле — овцы, части машин, товар, вода, трава, бабочки, ягоды, — идёт по часам игры: они идут со скоростью игры и стоят на паузе и под карточкой. Опускание поставленной машины, облачка и здание в руке идут в реальном времени.
- **Модели.** Файлов моделей нет: всё собрано в коде из мягких примитивов (скруглённые кубы, сферы, токарные ярусы) и склеено в одну геометрию с цветами вершин — одна модель, один вызов отрисовки или один instanced-меш на всех. `models.ts`: природа, овцы, товары, рынок, мелочи. `machineModels.ts`: машины. `kit.ts`: общие материалы и геометрии.
- **Машины.** Не домики, а механизмы, как в Tower Factory: у каждой свой силуэт и одна большая рабочая деталь, по которой видно, что она делает (ножницы на шатре, ясли с вилами, бадья с краской над аркой, щётка и огромный гребень, колпак сушилки и бигуди, клубок с огромными спицами, банька с трубой и паром, барабан-косилка, тележка с рукой, разбрасыватель семян). Машины стоят на светлых каменных подставках (ленты — дерево). Модель строится лицом на юг (dir 1) и поворачивается целиком вместе со зданием (`machineYaw` в `kit.ts`; то же в предпросмотре, подсветке и выборе лучом): у 2×1 машина стоит на задней клетке, то, что она наполняет, — на передней, где выход. Кусочков ленты на входах и выходах нет: вход и выход видны по самой модели (автор, 16.10.2026), на клетках из `inCell` и `outCells`. Вход — лоток-воронка между двумя столбиками с шариками цвета машины (`inlet`), выход — жёлоб вниз к краю с товаром машины на нём (`outlet`). У станций овцы входят и выходят через калитки, распахнутые по ходу, как у загона (`gates`); товар Стрижки идёт жёлобом направо, сено и краска въезжают в Кормушку и Покраску лотком справа (`sideInlet`). По овце видно, где она была (`render/sheepLook.ts`): гладкая шерсть, кудряшки, свитер, свалявшийся войлок — свои меши поверх, цвет — оттенок экземпляра. Загон в руке и на значке — та же модель забора с двумя проёмами. Подвижные детали заданы в `MachineSpec.parts` и двигаются, пока машина работает.
- **Загон** (`Pastures.tsx`): забор с двумя калитками, распахнутыми по ходу овец — наружу на выходе, внутрь на входе. Список загонов перечитывается, когда их строят и сносят.
- **Трава** (`Grass.tsx`, автор: «всю землю надо усыпать вот такой травой», потом «уменьшил бы траву, её высоту уж точно»). Густой низкий газон из широких листьев от тёмного основания к светлому кончику покрывает всю свободную землю (автор: «не должно быть проплешин», «опусти ещё процентов на 30%»):
  - пучки стоят сеткой 6×6 на клетку со сдвигом, поэтому густо везде, без пустот между случайными кучками;
  - растёт и вокруг деревьев, камней и кустов, они стоят в траве;
  - у постройки или ленты он становится короче и чуть темнее, без голой полосы;
  - каждый пучок повёрнут к камере, как бы её ни повернули (`uYaw` в шейдере);
  - его нет на постройках, лентах, воде, покосе, загоне и там, где лежит товар;
  - качается на ветру (сдвиг вершин в шейдере);
  - нормали смотрят вверх, поэтому газон освещается одной мягкой поверхностью;
  - не пишет глубину, поэтому контактные тени видят землю под ним, а не тысячи краёв листьев; рисуется после остального, от дальних пучков к ближним;
  - по умолчанию выключен, включается кнопкой внизу справа (`useAppStore.grass`, хранится в `ovf.grass`);
- **Остров растёт** (`render/island.ts`). Поле — 56×56 клеток, участки 8×8, 7×7 участков; остров — его часть от `Field.left` до `Field.right` и от `Field.top` до `Field.bottom` (`onIsland` в `grid.ts`, `inIsland` в `island.ts`). Этапы роста — `ISLAND_GROW` в `balance.ts`: уровень и новые края, кольцом вокруг стартовых 3×3 участков (`growIsland` в `systems/village.ts`). Остров — поле и `ISLAND.margin` = 1 клетка травы вокруг. Забор края (`Props.tsx`) идёт по краю поля со всех сторон, ёлки — на этой кромке, по одной в середине клетки: какие клетки, решает `rimTree` в `island.ts` (доля `RIM.trees`; цветы `Decor` их обходят). Пашня за краем острова, ещё под небом, не рисуется ни снопами, ни землёй. Части острова — земля, вода, холмы, заборы, рельеф, трава, цветы, деревья — читают края `island` и его холмы, когда строятся; `Island` в `Scene.tsx` строит их заново, когда край сдвигается. Камера тоже доходит до края. Рельеф под небом не рисуется.
- **Холмы** (`Hills.tsx`, `hillShape.ts`). Карта холмов — `MAP_HILLS` в `balance.ts`: прямоугольники второго и третьего уровня, третий — на втором. В мире они лежат в `Field.hills` (уровень по клетке), спрашивают их через `levelAt` в `grid.ts`. На холме `whyNot` отвечает `hill`: ни постройки, ни ленты, ни загона, ни овцы. Холм — не свободная клетка (`freeCell`): маршрут ленты его обходит, сеялка на него не сеет, кучка на него не ложится. Овца не ступает на холм (`grazeable`, `walkable` в `systems/sheep.ts`). Луч курсора сначала ищет верх холма третьего уровня, потом второго, потом землю (`Pointer.tsx`); призрак стройки висит над верхом холма (`Ghost.tsx`). Тесты правил снимают холмы и рельеф карты (`openField` в `game/testing.ts`). Вид — как у самого острова: каждый прямоугольник — ступень земли со скруглёнными углами (`rounded` из `Ground.tsx`), над ней травяная шапка, её край нависает над землёй; шапка третьего уровня светлее (`LOOK.hill.high`). Тень бросает только земля ступени. Высота ступени — `HILL.tier`. `hillHeight` и `onHillTop` говорят, где верх холма: там растёт трава (`Grass.tsx`), стоят ёлки и цветы. Цветы `Decor` холмы обходят.
- **Вода** (`Water.tsx`). Клетки воды — игровые квадраты, но рисунок — нет. Строится поле по 8 точек на клетку, у всех клеток воды вес один. Его размывает квадратный фильтр в полклетки (`WATER.blur`). Изолиния 0,56 — это берег: прямые остаются прямыми, выпуклые углы скругляются, вогнутые получают плавный переход.
  - Поверхность — внутренность изолинии (marching squares) на высоте 0,035, неосвещённая. Цвет ступенями по расстоянию до берега считается в шейдере по расстоянию, которое несут вершины (у берега — из размытого поля, глубже — двухпроходная фаска), поэтому края полос ровные: пена, мелководье, вода, глубина.
  - Бортик — полукруглый профиль, протянутый вдоль сглаженного (Chaikin) контура; направление обхода решает, куда «наружу».
  - Кувшинки и бегущие блики — instanced. Всё перестраивается при изменении воды.
  - Моря нет: остров висит на голубом фоне (`LOOK.sky`).
  - **Рынок** (`Market.tsx`). Одна модель на 8×8 (`marketHall` в `models.ts`): каменный цоколь с пастельной плиткой вокруг зала, нижний ярус с двумя дверями на каждой стороне — по одной у каждого входа — и товаром между ними, полосатый навес по кругу (`awning`: полосы с низом потемнее — он же даёт тень — и зубчатый край), над ним низкий второй ярус с окнами и ставнями под мятной крышей с фонариком и монетой (`MARKET_COIN_Y`). Каждый вход — лоток по площадке к двери: тёмное дно с кремовыми шевронами внутрь, коралловые бортики, у края два столбика с шариками. Вывесок нет: клиенты — в интерфейсе. Забор своей земли вдоль площадки рынка не ставится (`PlotFence.tsx`).
    - Событие `deliver` (`FxView` → `startFlight`): товар подпрыгивает у края лотка и съезжает по нему в дверь.
    - Событие `take` (`startCoin`): с монеты на крыше взлетает монетка.
    - Рынок обводится и выбирается, как постройка; его окно — клиенты с полосками и складом, а с торговлей — ещё и она.
- **Забор своей земли** (`PlotFence.tsx`). Пролёты забора с края острова стоят по каждой границе между двумя клетками поля, где своя земля встречает продажную; у края острова (где за клеткой небо) их нет — там стоит забор края (`Props.tsx`); над водой их нет, на концах ставятся отдельные столбики. Перестраивается при покупке участка.
- **Мелочи.** `Decor`: цветы и грибы только кучками (вдвое реже: автор), у заборов, воды, построек и края; под постройкой исчезают. Рисуются после травы. `Props`: тёплые каменные плиты у площадок, заборчик по краю, деревья по дальнему краю.

### 4.2.1 Свет и подсветка
- **Мультяшный свет.** Материалы `MeshToonMaterial` с тремя полосами света, тёплое солнце, небесная подсветка, мягкие тени.
- **Без пост-обработки.** Холст рисует прямо на экран, сглаживание — встроенное MSAA браузера, тональной коррекции нет (`flat`): цвета выходят как в палитре. Пост-обработка (N8AO, MSAA в своём буфере) стоила 13 мс из 15 на кадр, сама сцена — 2. Её убрали, когда автор попросил ускорить игру.
- **Контактные тени.** Мягкий тёмный ореол у основания каждой постройки, ленты и загона нарисован в текстуре земли (`Ground.tsx`, `CONTACT` в `balance.ts`). Он перерисовывается вместе с землёй, только когда что-то построили или убрали.
- **Тени солнца.** Карта 2048 (`SHADOW`). Солнце слева сзади (`LIGHT.sunFrom`), тени ложатся вправо вниз, как в Tower Factory, около 0,4 клетки на клетку высоты (автор). Плоское — ложе лент, плитка — тени не отбрасывает, только принимает.
  Все числа — `CONTACT`, `SHADOW`, `LIGHT` в `balance.ts`. Обводки нет: автор её убрал.
- **Подсветка** (`Hover.tsx`). То, что под рукой (машина, площадка, овца), обводится тёплой светлой линией по силуэту. Проход рисуется, только пока что-то подсвечено. Это пакет `@kit/outline` из Cubocalypse (без скиннинга толпы): в буфер id попадает только этот объект, все его части с одним id, так что линия идёт по внешнему краю. `views` (`pick.ts`) хранит объекты сцены по клетке постройки и id овцы. Овцу под курсором находит луч по её модели (`pickAt`): сначала дешёвые сферы, потом точная модель только у тех, через чьи сферы прошёл луч; берётся ближняя к камере. Раньше брали овцу у точки на земле под курсором, а она лежит за спиной овцы, поэтому выделялась задняя. Это же работает для клика и перетаскивания, а под неподвижным курсором пересчитывается каждый кадр.
- **FPS.** Готовая панель `Stats` из drei (stats.js) внизу слева; клик переключает FPS, мс и память.
- **Камера.** Наклон 36°, узкий объектив (fov 20) издалека, как на образцах-диорамах: видна высота машин, а высокие предметы не заваливаются к краям экрана. Камера поворачивается вокруг точки взгляда (`cam.yaw`: Option- или правая кнопка с протяжкой, Q/E, два пальца вбок), наклон постоянный. WASD двигают камеру относительно взгляда.
- **Цена кадра.** Мелким деталям меньше граней: шарик меньше 0,05 клетки — 6 сегментов, скруглённый брусок тоньше 0,15 клетки — 1 сегмент скругления, крупнее — 2. Модели индексированы (`model` в `kit.ts`): общие вершины считаются один раз, вершин вчетверо-впятеро меньше; детали без индекса (скруглённые бруски) склеиваются по битам. Земля острова — один плоский скруглённый прямоугольник, а не сетка в 240 тыс. треугольников. Пачки instanced-мешей каждый кадр отправляют в видеокарту только занятую часть (`upload` в `instancing.ts`). Весь кадр с ожиданием видеокарты — около 2,5 мс при плотности пикселей 2 (окно 3420×1792), с травой — около 4. Треугольников около 0,9 млн вместе с проходом теней. Мерить — `__game.bench()`.
- **Много одинаковых — один вызов.** Овцы (ноги, шуба каждого вида, кудряшки, свитер, стриженое тело, голова, хохолок; веки на время моргания; `render/sheepLook.ts`, пушистая овца — около 3 тыс. треугольников; свой мягкий свет `sheepVmat` в `kit.ts` — четыре слитые полосы тона и светлая тень), корпуса и движущиеся части машин, — instanced-меши, расставляемые за один проход кадра. Стадо до 5000 овец (`SHEEP.most`, под столько выделены меши): тень овцы отбрасывают три простых комка (`sheepShade*` в `models.ts`), а не все её детали; дальше `CAMERA.plainFlock` (56 клеток, обратно — ближе 50) овцы рисуются упрощёнными (`plain` в `models.ts`: вдвое меньше граней по кругу у каждой детали, то есть вчетверо меньше треугольников — 3,6 тыс. → ~1 тыс.; глаза полные, без блика и румянца); овцы вне кадра не расставляются; позы считаются прямо в матрицы (`standAt`), без `compose`. Пузырь «пора стричь» над овцой — карточка ещё одного instanced-меша, повёрнутая к камере (`bubbleMaterial` в `iconSprite.ts`): 26 пикселей на экране, но не больше половины клетки (`BUBBLE`), так что издалека пузыри мельчают вместе с овцами; ближние ложатся поверх дальних. HTML остаётся только у овцы, которую сейчас стригут (точки щелчков). Планка ленты — простой брусок, бортики — со скруглением в одну фаску: их на большой фабрике тысяча. Подсветка и выбор овцы или машины идут через невидимую копию модели в её позе (`pick.ts`, `Hover.tsx`): копия рисуется только в буфер id обводки.
- **Плотность пикселей сама подстраивается** под частоту кадров (`PerformanceMonitor` из drei): от 1 до плотности экрана, шагом 0,1. Если кадров не хватает, картинка чуть мягче, но не тормозит.
- **Стресс-тест.** `game/stress.ts` строит фабрику больше всей главы: показательную, весь остров куплен, на каждом внешнем участке — кольцо ленты, где через клетку едет товар, и три работающие машины; загоны полны (по 4), остальные овцы пасутся по всему острову. Машины поддерживаются запасом (`feedStress`). В браузере — `__game.stress(n)`, в тестах — `stress.test.ts`: шаг симуляции меньше 1 мс, товар движется, машины работают. Кадр такой фабрики при плотности 2 (3024×1678, Apple M5, весь остров в кадре): 3000 овец — 7 мс, 4000 — 9, 5000 — 10–11, 6000 — 12–13, 8000 — 15, 10 000 — 18; на 55 клетках, где овцы ещё полные, — 6 мс с 3000. Скорость ×4 почти не добавляет. Шаг симуляции с 4000 овцами — около 1 мс (было 12: каждая овца перебирала всё стадо, выход загона пробовали все его овцы по очереди, пасущиеся проверяли клетку каждый шаг через строковые ключи).
- **Проверка.** Правила и чек-лист — [04-ART.md](04-ART.md). Кадры сверяет отдельный агент-критик: он сравнивает их с образцами и чек-листом.

### 4.3 HUD
React DOM поверх холста (`ui/Hud.tsx`, один файл стилей `styles.css`, БЭМ-классы). Данные HUD — простой снимок в `useHudStore`. Клики в HUD сразу действуют на мир (`actions/*`), следующее обновление показывает результат.

**Ножницы** (`ui/ShearCursor.tsx`). Пока рука над пушистой овцой (не на паузе, не тащит), за курсором идёт SVG ножниц, а сам курсор над холстом прячется (`body.is-shearing`). Каждая половина — один рычаг через винт: лезвие с одной стороны, кольцо с другой, поэтому раскрываются вместе. На клик (`pointerdown`) класс `shear--snip` на 0,18 с: лезвия смыкаются и раскрываются, ножницы кивают. Под ними `HAND.shearClicks` точек, закрашены по `SheepT.clicks`. После последнего щелчка ножницы держатся ещё 200 мс, чтобы щелчок был виден. Читает мир каждый кадр сам, мимо `useHudStore`.
- **Значки** (`ui/Icon.tsx`). Постройки, товары, ресурсы, овца, монета и ножницы — картинки `public/icons/<kind>.png`, отрисованные из их же моделей (`render/iconRender.ts`): тот же свет и полосы тона, что в поле, ортокамера спереди-справа-сверху по рамке модели, рисуется в 512 пикселей и ужимается до 160, под ней тёмная обводка. Список — `ui/iconKinds.ts`. Если модель изменилась, в дев-сборке надо выполнить `__game.icons()`: картинки перерисуются и сохранятся. Когда поле не запущено (скрытая вкладка), то же делает `(await import('/src/render/iconRender.ts')).renderIcons()`, а лист овец — `(await import('/src/render/sheepSheet.ts')).renderSheepSheet()`. Нарисованы остались только крестик сноса, замок и переключатель травы.

## 5. Бот баланса

`bot.ts`: `createBot(world).act()` раз в 0,7 с игрового времени. Бот играет длинную игру по правилам самой игры.
- **Стройка.** Строит схему `plan.ts` как игрок — по кусочку, как приходят монеты (`pieces`): сначала участки работы, каждый рядом со своим (`jobPlots` находит их по клеткам самой работы), потом постройки по порядку; снятая лента идёт вместе с тем, что встаёт на её место, чтобы петля не рвалась, а второй загон на углу петли ставится разом (`whole`). Работа ждёт, пока её земля под небом (`landReady`). Схема — семь загонов на шести петлях вокруг рынка, у каждой петли свой товар и свой вход в рынок (заголовок `plan.ts`): A на стартовой земле к западу от рынка — шерсть, второй загон стоит на углу её петли (овцы проходят чужой загон насквозь); W к северу — пряжа; E к югу — нитки; X к востоку от E, у пруда, — войлок, через объединитель в линию E; S к востоку — цветная шерсть; Y на дальнем юге — свитер, по столбцу 16 в рынок. Петля идёт от загона на восток и назад рядом выше; товар для станции приходит справа, снизу; товар Стрижки падает рядом ниже и бежит к рынку. Холмов на пути схемы нет. Плюс сенокос и кормушка к каждой.
- **Рука.** Одна, как у игрока: каждый подход — взять, положить, клик — стоит `BOT.hand.act` секунд, и между ними она идёт `BOT.hand.speed` клеток в секунду. Каждое дело — дойти и взять, потом дойти и положить. По порядку: бродячую овцу — в загон с местом; кучки на земле — на рынок, пока не наделано новых; голодной без кормушки — сено в руке (кучка, собранное с покоса прямо в руку или купленное); пушистую без петли — постричь (шерсть падает рядом); тупики лент — на рынок. Сеет из руки, когда покоса мало. Овец докупает в каждый загон, где есть место, но не пока кто-то бродит. Краска идёт в Покраску всегда: её петля одна, и её цветную шерсть берёт Школа.
- **Ограничение.** Машины бот рукой не загружает, хотя игрок может (GDD 3): так его время — время фермы на лентах.

`runBot(world, seconds, until)` играет без отрисовки и отдаёт по каждому уровню (`LevelRun`): сколько он шёл, сколько покупок, самую долгую паузу между ними, сколько бот копил и сколько ему нечего было купить, заработано, потрачено, монеты и овцы в конце; и какую работу схемы на каком уровне построил. Тест `bot.test.ts` (`pnpm simulate`) проверяет, что глава 1 закрывается за 75 минут, и печатает эту таблицу; сейчас — к 34:42, 29 овец, 11 участков, без дела 21:09. Бот строит всю схему сразу, как только уровень её открывает, поэтому уровни без новой станции он проходит за полторы минуты: спрос на каждом уровне — 85–90% того, что везёт его ферма (у Ярмарки меньше), так что игроку с фермой попроще придётся её растить. Бесконечный режим он доводит до 21-го уровня к 70 минутам. Та же рука ухаживает за фермой за главным меню (`buildShowcase` возвращает её, `TitleScreen` зовёт её раз в 0,7 с). Модель экономики без самой игры — `docs/econ/model.mjs` (05-REWORK, раздел 7).

## 6. Дев-инструменты

`window.__game` есть только в дев-сборке:

| Что | Что делает |
|---|---|
| `world`, `res(T)`, `traits` | доступ к живому миру |
| `coins(n)` | добавить монет |
| `shot(name)` | сохранить кадр 3D в полном разрешении в `docs/concept/shots/<name>.png` (без HUD) |
| `look(x, z, dist, yaw)` | поставить камеру над точкой поля, повернуть на `yaw` градусов |
| `info()` | частота кадров и время кадра на процессоре |
| `icons()` | перерисовать значки из моделей в `public/icons` |
| `sheep()` | нарисовать все виды овец на одном листе `docs/concept/shots/sheep-sheet.png` (`render/sheepSheet.ts`) |
| `stress(sheep)` | построить огромную рабочую фабрику для замеров (`game/stress.ts`) |
| `bench(n)` | сколько мс стоит целый кадр (симуляция, виды, тени, отрисовка) с ожиданием видеокарты |
| `r3f()` | состояние R3F, например его покадровые подписчики — чтобы засечь каждый |
| `app.setState({ grass })` | переключатели без сохранения |
| `speed(n)` | скорость |
| `start()` | начать новую игру |
| `unlockAll()` | открыть все постройки |
| `autoplay(on, speed)` | бот играет вживую |
| `simulate(seconds)` | бот играет без отрисовки, печатает время уровней |
| `showcase(warmup)` | достроить в этом мире готовую ферму главы (`plan.ts`) |
| `project(x, z)` | точка поля → экран, для сценарных кликов |

Адрес `?play` сразу открывает игру, `?play&endless` — бесконечный режим (только в дев-сборке).
